# Decisões técnicas

| Tema | Decisão | Por quê |
|---|---|---|
| Stack | React 18 + Vite + TypeScript + Three.js/R3F/drei (a mesma do FigureBox) no cliente; Node + Express no servidor | Reaproveitar o editor sem reescrever a camada 3D. Express é simples e conhecido |
| Projeto | Pasta e repositório git **independentes** (`Workscape 3D/`). O FigureBox foi só lido de um clone temporário | Pedido do briefing: manter o FigureBox intacto |
| Banco | SQL portátil com dois drivers: **SQLite embutido do Node** (`node:sqlite`) para o caminho local e **MariaDB** (`mysql2`) para produção | Rodar localmente sem instalar nada (nenhum MariaDB ou Docker disponível nesta máquina) e manter o alvo de produção pedido. O driver SQLite serializa as operações numa fila e usa `BEGIN IMMEDIATE` nas transações |
| Unidades e eixos | Metros, Y para cima, frente dos assets em +Z, pivô no centro da base (ou centro da face traseira, para parede) | Um único contrato para pipeline, editor e servidor. A normalização é feita **offline**, e o cliente só clona |
| Modelo de dados | `AssetDefinition` (arquivo, licença, medidas, pivô, versão) ≠ `SceneObject` (assetId, transform local, pai, andar, tipo) ≠ `OfficeRevision` ≠ `SeatAssignment` ≠ `EmployeeDirectoryEntry` (`employees`) ≠ `ManagedDevice` ≠ `IntegrationBinding` ≠ `ActionAudit` | Pedido do briefing. Um GLB alimenta muitas instâncias, e vínculos não dependem do visual |
| Hierarquia | Transform **local** ao pai. O mundo é composto em `worldTransform` | "Computador acompanha a mesa" sai de graça. A validação recusa ciclos, pai inexistente e profundidade acima de 8 |
| Capacidades | Ações por **tipo funcional** (`workstation`, `printer`, `tv`, `room`) **e** vínculo validado no servidor | Nunca pelo nome da malha. Trocar o modelo não muda capacidades nem vínculos |
| Rascunho e publicação | O rascunho fica em `offices.draft_json` com `draft_version`. Gravar exige `baseVersion`, e versão diferente devolve 409 com quem gravou e quando. Publicar é uma transação: `UPDATE … WHERE draft_version = ?` troca o ponteiro e insere a revisão imutável | Gravação concorrente detectada, sem sobrescrita silenciosa. A publicação é atômica (dois publicadores não passam juntos) |
| Vínculos fora da revisão | Colaborador, dispositivo e painel são dados operacionais, valem na hora e apontam para o ID do objeto | Uma troca de mesa não deve exigir publicar o mapa. Se o objeto some da revisão ou do rascunho, o vínculo aparece como **órfão** para o administrador |
| Colisões | Aviso (borda âmbar + contagem), não bloqueio | Sobreposição legítima: cadeira sob a mesa, tapete, item sobre o tampo |
| Autorização | Perfis `admin`, `operator` e `viewer`. Todas as consultas filtram por `company_id` da sessão; ID de outra empresa → 404. Acesso remoto também filtrado por dispositivo (`remote_access_grants`) | Escopo por empresa **e** por recurso no servidor |
| Sessão | Cookie HttpOnly + SameSite=Strict. O token guardado é só o hash SHA-256; senha com scrypt. Mutações exigem o cabeçalho `X-Requested-With: office3d`. Limite simples de tentativas de login | Sem token no JavaScript. Proteção contra CSRF em duas camadas |
| Idempotência | Tabela `idempotency_keys` (usuário + escopo + chave). Repetições recebem a mesma resposta (`replayed`). Chave reutilizada com outro conteúdo → 422 | Duplo clique e retry em transferência e impressão. A impressão também reaproveita o trabalho idêntico de até 15 s atrás (chaves diferentes) |
| Concorrência na transferência | `UPDATE service_tickets … WHERE assignee = operador AND status = 'active' AND version = ?` | Nunca transferir um atendimento que já mudou |
| Estados das ações | `available`, `not_configured`, `forbidden`, `unavailable` calculados no servidor e reavaliados na execução. Resultados com `mode: demo/real` | A interface mostra exatamente o contrato. O modo demonstração nunca se passa por serviço real |
| Indisponibilidade | O erro do conector vira 503 só para a ação. Presença indisponível aparece como "Presença indisponível", nunca como mesa vaga | O mapa e a edição continuam funcionando |
| Acesso remoto | O AnyDesk usa o mecanismo documentado (cliente oficial com o endereço do dispositivo). O link `anydesk:` só com `ANYDESK_LAUNCH=uri`, depois de validação | Não implementar execução de comandos, senha nem conexão automática (briefing) |
| Impressão | Diálogo do navegador + envio direto opcional por adaptador. Três estados distintos (diálogo, envio confirmado, conclusão) | O navegador não escolhe a impressora nem comprova a impressão (briefing) |
| Painéis | Só `/demo/…` ou `https://` de host listado; `iframe` com sandbox; a CSP limita `frame-src` | Não abrir URL arbitrária vinda do banco |
| CSP | `default-src 'self'`, sem scripts ou estilos de terceiros. Ambiente de iluminação procedural (sem HDRI baixado) | Assets aprovados servidos localmente. Recursos externos bloqueados |
| Renderização | Cache de GLB com contagem de referências; `clone(true)` compartilha geometria e material; `InstancedMesh` para repetidos (4 ou mais) e não acionáveis no modo operação; paredes do lado da câmera baixam para 25 cm | Desempenho e leitura da planta isométrica. Ideias do FigureBox (cache e parede) adaptadas |
| Falha de modelo | Caixa âmbar com as medidas do asset; asset fora do catálogo → caixa padrão | A cena nunca quebra por um arquivo ausente |
| Desfazer/refazer | Instantâneos imutáveis da lista de objetos (até 100). O arraste é um passo só (transiente → commit) | Simples e correto com hierarquia, grupo e troca de modelo |
| Testes | API testada contra o servidor real (porta livre, SQLite em memória); operações do editor como funções puras; aceite no navegador real com `playwright-core` + Chrome/Edge do sistema | Sem baixar navegadores. Os fluxos são os da interface, não chamadas diretas |
| Workscape | Adaptador reservado que responde "não configurado" | Sem documentação ou código do Workscape nesta entrega: nada de contrato inventado |
